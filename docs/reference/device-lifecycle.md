# Жизненный цикл устройства

## DeviceLocator

`DeviceLocator` — точка входа в SDK. Он создаётся один раз и живёт всё время работы с плагином. Через него происходит поиск устройств и создание объектов `Device`.

При создании можно передать путь к директории для логов SDK — если не передавать, логи не пишутся. После создания `DeviceLocator` сразу готов к работе.

Поиск устройств запускается через `requestDevices`. Метод неблокирующий: он инициирует BLE-сканирование и немедленно возвращает стрим, который эмитит ровно один раз — когда `searchTime` истёк и список устройств собран. Если Bluetooth выключен, стрим завершится ошибкой `BluetoothDisabledException`. Если ни одного устройства не найдено — придёт пустой список.

```dart
final locator = DeviceLocator();
final devices = await locator.requestDevices(
  type: DeviceType.any,
  searchTime: 5,
).first;
```

Для тестирования без железа можно передать `DeviceType.sinWave` или `DeviceType.noise` — SDK создаст симулятор устройства, который эмитит синтетические EEG-данные.

Когда работа с SDK завершена, нужно вызвать `locator.dispose()`. После этого все дальнейшие вызовы бросят `NeiryException`.

## Device

`Device` создаётся через `locator.createDevice(serial)` с серийным номером из результатов поиска. Объект создаётся в отключённом состоянии — подключение происходит отдельным вызовом.

### Состояния и переходы

Устройство проходит через состояния в строгом порядке. Подключение через `connect()` запускает BLE-рукопожатие в фоне — когда оно завершается, `connectionStateStream` эмитит `ConnectionState.connected`. После этого можно запускать стриминг через `start()`. Только с активным стримингом (после `start()`) становятся доступны EEG-данные и классификаторы.

```
createDevice()
  → connect()    → connectionStateStream: connected
    → start()    → eegStream, psdStream, классификаторы активны
    ← stop()
  ← disconnect()
```

Если вызвать `start()` до `connect()`, или создать классификатор до `start()` — Dart API бросит исключение, не дожидаясь ответа от платформы. Это намеренный инвариант: SDK не определяет, что происходит при нарушении порядка вызовов, поэтому плагин предотвращает это на уровне Dart.

### Подключение

`connect()` принимает флаг `bipolarChannels`. Когда он `true`, каналы попарно вычитаются — получаются биполярные сигналы, где каждое значение представляет разницу между двумя электродами. Для большинства сценариев это предпочтительно: убирает синфазные помехи. Значение по умолчанию — `false` (монополярный режим).

Подключение асинхронное и неблокирующее. `connect()` возвращает `Future<void>`, который завершается, когда платформа зарегистрировала запрос — но само соединение устанавливается в фоне. Актуальное состояние всегда можно наблюдать через `connectionStateStream`.

### Неожиданный обрыв связи

Если гарнитуру выключают или BLE-соединение теряется, `connectionStateStream` эмитит `ConnectionState.disconnected` — на Android с задержкой ~7 секунд после физического разрыва. Сессию при этом нужно завершить так же, как при ручном disconnect, а для нового подключения требуется повторный скан. Подробнее — [Завершение сессии](../guides/teardown.md).

### Режимы работы

После `start()` устройство переходит в один из режимов. Режим определяет, какие данные передаются:

- `Signal` — EEG-стриминг, данные идут в `eegStream` и `psdStream`
- `Resistance` — измерение импеданса электродов, данные идут в `resistanceStream`
- `SignalAndResist` — одновременно EEG и импеданс
- `StartMEMS` / `StopMEMS` — акселерометр и гироскоп
- `StartPPG` / `StopPPG` — фотоплетизмография (пульс)

Режим можно отслеживать через `modeChangedStream`. EEG-классификаторы требуют активного режима `Signal` или `SignalAndResist`.

### Информация об устройстве

Серийный номер, название и тип устройства доступны через `getInfo()`. Частоты дискретизации (EEG, PPG, MEMS) и амплитуды светодиодов PPG запрашиваются отдельными методами и зависят от конкретного устройства — их нужно читать после подключения, не раньше. Список каналов и их порядок тоже зависит от типа устройства: у наушников, обруча и Buds разная конфигурация электродов.

### Очистка ресурсов

При завершении работы устройство нужно корректно остановить и освободить:

```dart
await device.stop();
await device.disconnect();
device.dispose();
locator.dispose();
```

После `dispose()` объект нельзя использовать повторно. Если этого не сделать, нативный C SDK удержит дескриптор устройства в памяти до следующего перезапуска.
